چشم‌انداز پروژه
سیمون یک پلتفرم کامل SaaS (نرم‌افزار به عنوان سرویس) است که برای اتوماسیون کامل کسب‌وکارهای صنعت غذا و مهمان‌نوازی (رستوران‌ها) طراحی شده است. هدف اصلی، کاهش هزینه‌ها، افزایش سرعت خدمت‌رسانی و ارائه تحلیل‌های داده‌محور به صاحبان کسب‌وکار است.

مشکل اصلی که حل می‌شود
جایگزینی فرآیندهای دستی مانند ثبت سفارش تلفنی، مدیریت کاغذی و تجربه‌های جداگانه برای مشتریان، با یک سیستم یکپارچه، دیجیتال و هوشمند.

دموی زنده پروژه
لینک دموی شما روی github.

📐 معماری کلی (High-Level Architecture)
این پروژه یک اپلیکیشن Full-Stack با جداسازی کامل مسئولیت‌ها است که برای مقیاس‌پذیری و نگهداری آسان طراحی شده.

جریان داده
مرورگر کاربر (فرانت‌اند) -> درخواست API (از طریق /github/Vercel/Netlify) -> سرور بک‌اند (روی Render) -> پایگاه داده (Supabase) -> پاسخ از طریق همان مسیر به کاربر برمی‌گردد

اجزای اصلی
فرانت‌اند (سمت کاربر)
یک اپلیکیشن تک‌صفحه‌ای (SPA) ساخته شده با جاوا اسکریپت خالص. مسئولیت اصلی آن، ساخت رابط کاربری (UI) و تجربه کاربری (UX) است. روی یک سرویس میزبانی فایل استاتیک مانند Vercel یا Netlify دیپلوی می‌شود.

ویژگی‌های کلیدی:

نمایش محصولات با جزئیات کامل (نام، مواد اولیه، قیمت، موجودی)
سبد خرید هوشمند با قابلیت مدیریت تعداد و یادداشت‌های سفارشی
رابط کاربری واکنش‌گرا برای دستگاه‌های مختلف
انیمیشن‌های جذاب برای بهبود تجربه کاربری
بک‌اند (سمت سرور)
یک API از نوع RESTful ساخته شده با Node.js و Express.js. تمام منطق‌های تجاری، پردازش داده‌ها و ارتباط با پایگاه داده را مدیریت می‌کند. روی یک پلتفرم PaaS مانند Render دیپلوی می‌شود.

API Endpoints اصلی:

GET /api/menu - دریافت تمام آیتم‌های منو با مواد اولیه
GET /api/menu/:id - دریافت یک محصول خاص
POST /api/admin/menu - ایجاد محصول جدید
PUT /api/admin/menu/:id - ویرایش محصول موجود
DELETE /api/admin/menu/:id - حذف محصول
GET /api/admin/custom-categories - دریافت دسته‌بندی‌های سفارشی
پایگاه داده (لایه داده)
یک پایگاه داده PostgreSQL که توسط Supabase مدیریت می‌شود. تمام داده‌های پایدار شامل منوها، سفارش‌ها، اطلاعات کاربران و داده‌های چند مشتره (Multi-Tenant) را در خود ذخیره می‌کند. Supabase همچنین خدمات احراز هویت و Realtime را نیز فراهم می‌کند.

ساختار جداول:

menu_items - اطلاعات محصولات اصلی
ingredients - مواد اولیه
product_ingredients - ارتباط بین محصولات و مواد اولیه
custom_categories - دسته‌بندی‌های سفارشی

### `js/app.js`
نقطه ورودی (Entry Point) برنامه. این فایل مسئولیت‌های زیر را بر عهده دارد:
-   **شنوننده رویداد `DOMContentLoaded`:** منتظر می‌ماند تا کل DOM بارگذاری شود و سپس برنامه را مقداردهی اولیه (Initialize) می‌کند.
-   **تنظیم Event Listeners:** رویدادهای کلیک روی دکمه‌های دسته اصلی، زیردسته‌ها، لینک‌های ناوبری و... را مدیریت می‌کند.
-   **مقداردهی اولیه برنامه:** با فراخوانی `showPage('home')` و توابع دیگر، وضعیت اولیه صفحه را تنظیم می‌کند.
-   **اتصال به `window`:** توابعی مانند `changeQuantity` و `removeFromOrder` را به شیء `window` متصل می‌کند تا بتوان از طریق ویژگی‌های `onclick` در HTML به آن‌ها دسترسی داشت.

### `js/config.js`
قلب تپنده (Central Hub) برنامه. این فایل تمام داده‌های متغیر (Stateful) و تنظیمات را در خود جای می‌دهد.
-   **`state`:** یک شیء (Object) که وضعیت فعلی برنامه را نگهداری می‌کند. شامل متغیرهایی مانند `currentMainCategory`، `order` و `favorites` است. تغییر این `state` در تمام فایل‌های دیگر باعث آپدیت شدن رابط کاربری می‌شود.
-   **`elements`:** یک شیء که عناصر مهم DOM را کش (Cache) می‌کند. این کار از کوئری‌های مکرر به DOM جلوگیری کرده و عملکرد را بهبود می‌بخشد.
-   **`config`:** یک شیء برای تنظیمات ثابت برنامه مانند `mobileBreakpoint` و زمان‌بندی کروسل‌ها.

### `js/data.js`
شامل تمام داده‌های استاتیک و ثابت برنامه.
-   **`allMenuItems`:** آرایه‌ای از اشیاء که تمام آیتم‌های منو با جزئیات کامل (نام، قیمت، تصویر، دسته و...) را در خود جای می‌دهد.
-   **`categoryData`:** شیئی که توضیحات هر دسته اصلی را نگهداری می‌کند.
-   **`specialsAlbumData`:** داده‌های مورد نیاز برای کروسل تصاویر در صفحه "ویژه‌ها" (Specials).

### `js/menu.js`
بزرگ‌ترین فایل پروژه که تمام منطق مربوط به منو، سفارش و رابط کاربری را در خود جای داده است.
-   **`renderProducts()`:** آیتم‌های منو را بر اساس دسته اصلی و فرعی انتخاب شده فیلتر کرده و آن‌ها را در صفحه رندر می‌کند.
-   **`addToOrder()`:** محصولی را به سبد خرید اضافه می‌کند، انیمیشن "تصویر پرنده" را اجرا کرده و UI را آپدیت می‌کند.
-   **`changeQuantity()` و `removeFromOrder()`:** تعداد محصولات را تغییر داده یا آن‌ها را از سبد حذف می‌کند.
-   **`submitOrder()`:** در نهایت سفارش را پردازش و تأیید می‌کند.
-   **`showPage()`:** تابع اصلی برای نمایش و پنهان کردن صفحات مختلف (خانه، منو و...). همچنین مسئول مدیریت وضعیت تب‌های اصلی منو است.
-   **`updateNavigationWrapper()`:** توابعی برای مدیریت بک‌گراند ناوبری در موبایل.
-   **`updateCategoryDisplay()`:** بخش نمایش دسته (شامل عنوان، تصویر و توضیحات) را آپدیت می‌کند. منطق مخصوصی برای حالت "ویژه‌ها" (Specials) دارد.
-   **`updateSubCategoryNav()`:** دکمه‌های زیردسته را به صورت داینامیک ایجاد و مدیریت می‌کند.
-   **توابع کروسل و افکت:** توابعی مانند `nextSlide`، `startCategorySmoke` و... برای ایجاد تعاملات پویا در صفحه.

### `js/utils.js`
شامل توابع کمکی و قابل استفاده مجدد (Utility Functions).
-   **`formatPrice()`:** یک عدد را به فرمت قیمت (با علامت دلار) تبدیل می‌کند.
-   **`debounce()`:** یک تابع عمومی برای بهینه‌سازی رویدادهایی که به طور مکرر اجرا می‌شوند (مانند `resize` پنجره).

CREATE TABLE custom_categories (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    type VARCHAR(20) NOT NULL, -- 'category' or 'subcategory'
    parent_category VARCHAR(100),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

product_ingredients
CREATE TABLE product_ingredients (
    id SERIAL PRIMARY KEY,
    product_id INTEGER REFERENCES menu_items(id) ON DELETE CASCADE,
    ingredient_id INTEGER REFERENCES ingredients(id) ON DELETE CASCADE,
    quantity DECIMAL(10,2) NOT NULL,
    UNIQUE(product_id, ingredient_id)
);





ingredients
CREATE TABLE ingredients (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    unit VARCHAR(20) NOT NULL DEFAULT 'گرم',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

menu_items

CREATE TABLE menu_items (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    description TEXT,
    price DECIMAL(10,2) NOT NULL,
    image VARCHAR(255),
    category VARCHAR(100) NOT NULL,
    sub_category VARCHAR(100),
    is_special BOOLEAN DEFAULT FALSE,
    stock_quantity INTEGER DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
